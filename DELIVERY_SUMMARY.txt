1. User Service (Port 8081)
   ├─ 6 REST endpoints
   ├─ User CRUD operations
   ├─ User validation & authentication
   └─ No Feign calls

   ├─ 7 REST endpoints
   ├─ Post CRUD operations
   ├─ Calls User Service & Tag Service via Feign
   ├─ Search functionality
   └─ Circuit breakers (Resilience4j)

   ├─ 7 REST endpoints
   ├─ Comment CRUD operations

   └─ Feign client with Resilience4j circuit breaker

KNOWN GAPS & NEXT ADDITIONS
═══════════════════════════════════════════════════════════════════════════

The platform is functional and deployed, but several production-grade
concerns remain open. Captured here as an honest backlog:

  Gap                                        Where it fits
  ─────────────────────────────────────────  ────────────────────────────────
  Retry + bulkhead                           Finishes Phase 4 (resilience)
  Schema/DB isolation                        All services share one main_db —
                                             a shared-database coupling
  DB migrations (Flyway/Liquibase)           Replaces hibernate ddl-auto=update
  Automated tests + CI/CD                    Builds use -DskipTests; no suite;
                                             Docker builds are manual
  API docs (OpenAPI/Swagger, springdoc)      Aggregate at the gateway
  Distributed tracing (Micrometer→OTLP/      Pairs with the gateway's existing
    Zipkin/Jaeger)                           RequestTrackingFilter
  Auth/security (JWT/OAuth2 at gateway)      Gateway has CORS but no auth
  Metrics aggregation (Prometheus/Grafana)   Actuator exposed, nothing scrapes
  Centralized config (Spring Cloud Config)   Each service has its own YAML
  Rate limiting at the gateway               Fits alongside a Redis layer

Suggested order of value:
  1. Retry + bulkhead — finish what Phase 4 already promises
  2. Flyway migrations + a basic test suite + CI — biggest safety gap
  3. Distributed tracing — high value once services talk
  4. Auth at the gateway, then Prometheus/Grafana and a config server

Each item is a focused, multi-step change — tackle as its own increment.
