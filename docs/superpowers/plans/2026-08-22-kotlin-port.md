# Kotlin Port of Blog Microservices Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Produce a functionally identical Kotlin copy of this Java/Spring Boot microservices project at a sibling path, with zero behavior/API/port changes.

**Architecture:** Same 7-module Maven reactor (`eureka-server`, `api-gateway`, `user-service`, `post-service`, `comment-service`, `like-dislike-service`, `tag-service`) plus a copied-unmodified `frontend/`. Java sources under `src/main/java` become Kotlin sources under `src/main/kotlin`, 1:1, same package/class/method names. Kotlin support is added once at the parent `pom.xml`; module poms are otherwise untouched.

**Tech Stack:** Kotlin (via `kotlin-maven-plugin`, `jpa`/`spring` compiler plugins, `jackson-module-kotlin`), Spring Boot 3.3.0, Spring Cloud 2023.0.3, Java 17 target, Maven multi-module, Docker Compose (Postgres, Redis, Kafka/Zookeeper, Eureka).

**Spec:** `docs/superpowers/specs/2026-08-22-kotlin-port-design.md`

## Global Constraints

- Source of truth: commit `054b625` (HEAD) of the current Java repo at `/Users/shosingh_1/Downloads/osapiens/-blog-microservices`.
- New repo root: `/Users/shosingh_1/Downloads/osapiens/blog-microservices-kotlin/` (new standalone git repo).
- Package names, class names, method names, field names, and REST/Feign/Kafka contracts stay **identical** to the Java originals — this is a language port, not a redesign.
- JPA `@Entity` classes → plain Kotlin classes (NOT `data class` — Hibernate needs mutable, identity-based objects). Kept open via the `kotlin-jpa` compiler plugin, so no manual `open` keyword needed.
- DTOs / request-response bodies → Kotlin `data class`.
- Controllers, `@Service`, `@Repository`, `@FeignClient` interfaces, `@KafkaListener` methods, `@Configuration` classes → direct 1:1 translation, same annotations and attributes.
- No Lombok in this codebase — nothing to strip.
- Logging: `private val logger = LoggerFactory.getLogger(ClassName::class.java)` as a class-level `val`, preserving every existing log call and level.
- Spring Data repository methods returning `Optional<T>` stay `Optional<T>` (not converted to nullable Kotlin types) — matches Spring Data JPA's expected return type.
- `docker-compose.yml`, all `Dockerfile`s, all `application.yml`s, and env vars are copied byte-for-byte unchanged (same ports: Eureka 8761, Gateway 8080, user 8081, post 8082, comment 8083, like-dislike 8084, tag 8085, Postgres 5432, Redis 6379, Kafka 9092/29092, Zookeeper 2181).
- `frontend/` is copied unmodified (minus `node_modules`/`dist`, which are regenerated by `npm install`/build) — no code changes, same `localhost:8080` gateway URL.
- The Kotlin stack reuses the Java stack's ports — it's a drop-in replacement, run standalone. The original Java stack's `docker-compose` must be stopped before bringing up the Kotlin one.
- `post-service` depends on the `tag-service` module artifact (`com.blog:tag-service:1.0.0`) — Task 8 (post-service) must not start until Task 7 (tag-service) is complete.
